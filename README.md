# Civit Viewer 0.3

个人使用的独立 iPhone 客户端，连接 `https://civitai.red`。最低 iOS 17；界面和播放使用 SwiftUI、UIKit、AVFoundation、SafariServices；兼容修复包含固定版本的 FFmpeg 及 CivitMediaEngine，不运行外部辅助服务。依赖源码、许可证和构建脚本随工程保存，见 `Vendor/FFmpeg/README.md`。

## 代码分层与复用

界面层负责原生控件、导航和可见性；业务状态由对应的 model/store 持有。分页与时间线恢复分别有明确的提交资格，不让视图自己拼接请求、重建去重集合或决定旧响应能否写回。

| 部件 | 所有权与复用范围 |
|---|---|
| `MainTabs` | 生产页面和 UI 测试共用原生 TabView、NavigationStack、标签及底部点击入口；保留 SwiftUI 的 delegate 所有权。 |
| `TimelineModel` | 推荐／关注各持有一个实例，统一管理恢复、焦点提交、提示事件和明确重试资格。关闭提示不改变分页资格。 |
| `FeedStore` + `FeedRequest` | 时间线、搜索、作者作品、作品榜和收藏列表共用分页、去重与迟到结果保护；来源为明确的枚举。 |
| `MediaRead` | 时间线与历史入口共用一份有界作品恢复算法，包括批量读取、缺失作者 ID 补齐、取消及账号／关注快照检查。 |
| `MediaReading` | 构建31将分页读取、历史作品读取和时间线账号上下文拆成三个只读能力接口；业务层和测试替身使用同一份生产声明。 |
| `SiteSession` | 实现读取接口，继续作为登录、当前账号和远端关系的唯一权威源。不同 identity 保留各自失效含义，私有写入边界保留。 |
| `MediaDeck` / `MediaPageView` | 多入口共用整屏分页与作品呈现，导航回调由入口提供；视频和位图分别由 `VideoSurface`、`BitmapMediaSurface` 呈现。 |
| 历史、标签库、离线库、浏览缓存 | 各自管理持久化和容量；本批没有迁移 schema、账号目录、文件或 Keychain。 |

`FeedStore` 只依赖 `FeedPageReading`；`MediaRead` 只依赖 `HistoryMediaReading`；`TimelineModel` 使用组合后的 `TimelineReading`。这三个协议不包含登录、WebKit、凭据刷新或关注写入权限。三个测试替身分别实现对应协议，完整 App 编译同时核对真实 `SiteSession` 的实现。收藏页参数 `allAccessibleLevels` 明确传 `false`，保持构建30的实际默认值。

这一批完成的是核心取数边界。部分视图和播放器仍直接使用 `SiteSession` 或 `.shared`；传输与解码尚未从会话类中分离。后续改造要按真实所有权继续收窄这些依赖，不把增加接口的数量作为完成标准。`verify-session-boundary.py` 目前仍抽取生产传输函数做本地检查，不应把它解释为完整 App 网络层集成验收。

## 页面与浏览

底部为「时间线 / 作者榜 / 搜索 / 我」四个入口。时间线顶部为「关注 / 推荐」，下一层为「图片 / 全部 / 视频」。两个来源分别保留当前会话的筛选、列表、游标与浏览位置；构建24新增按账号保存的“接着看”记录。媒体文件使用同一份磁盘缓存。「推荐」使用站点公开热度排序，不声称自建个性化算法。

构建60新增本机筛选方案。时间线类型选择器左侧的书签进入方案列表；保存时可修改建议名称并核对条件预览，点选方案直接恢复筛选。推荐、关注、搜索分别存放，按稳定账号 ID 隔离，每个账号三个入口合计最多50项。搜索方案同时保留标题前缀、作者、最多8个标签，以及媒体类型、排序、时间、模型、PG与视频时长范围；在搜索首页载入后仍由用户明确提交搜索。列表支持重命名和确认删除。损坏或未知版本的方案文件保留并报错，不用丢失条件的版本覆盖。

关注时间线请求站点的 followed 流，并用当前账号的关注 ID 再核对一次作者；没有关注作者时保持空流。作者列表从关注时间线右上角或「我」进入。作者作品支持 Images / Videos 网格与整屏查看。作者页默认「全部时间、最新」，直接提供时间范围和排序菜单；也可在筛选面板选择模型与 PG。重置作者筛选保留当前媒体类型，并恢复作者默认值。从具体作品进入作者页时传递该作品的图片／视频类型。

作者榜固定为 **Master Generators (mature)**，ID `images-nsfw`。Seasonal 使用 `leaderboard.getLeaderboard`；Legacy 使用站点原有拼写 `leaderboard.getLeadboardLegends`，不自行重算名次。两个榜分别保留已加载列表与滚动位置，进入作者再返回不自动刷新，手动下拉更新。

媒体类型使用页面上方选择器；筛选面板提供热度/最新/评论/收藏排序、时间范围、基础模型、仅看PG和视频时长区间。时长条件仅用于视频，切换图片或全部时清除。重置保留当前媒体类型；仅默认筛选编辑保留独立媒体选择。选择即时生效，只有「完成」关闭，不提供无法撤销的「取消」或额外「应用」。连续修改合并约250ms再请求；先使旧请求上下文失效。关闭「仅看PG」时显式传入服务器读回的账号浏览范围，最终可见内容以站点规则为准。

## 播放与手势

- 上下滑：上一条 / 下一条作品。一页占满内容视区，裁剪相邻页面。
- 从屏幕左右约 30 pt 边缘起手横滑：按 Images / 全部 / Videos 切换，首尾不循环。拖动时画面跟手移动并提示目标类型，超过 45 pt 显示「松开切换」，不足阈值或取消时回弹。
- 双击图片或视频：进入当前作品的作者页；作者作品全屏查看内则返回该作者页。单击等待双击判定，避免同时触发暂停。
- 视频中央单击：暂停 / 继续。播放时没有常驻中央暂停图标，暂停时显示播放图标。
- 视频中央横拖：快退 / 快进，约 10 pt 对应 1 秒。结束后恢复原先的播放状态。
- 视频边缘长按 0.35 秒：临时 2×；松手恢复原先状态。
- 首次加载和播放中等待数据时显示状态；取得实际缓冲区间后显示缓冲到的时间点。构建27正常播放时底部仅显示细线，拖动或暂停时显示当前／总时长与单一滑块；可拖动或点按进度条，按可跳转范围定位。时长未知或不可跳转时禁用，不显示虚构百分比。VoiceOver 可按 5 秒调整。
- 观看页的方向按钮手动切换横竖屏；「我 → 播放 → 自动旋转」默认关闭并记住选择。手动按钮不改变自动旋转开关，退出观看页恢复父页面策略；方向请求被系统拒绝时保留明确提示。

顶部切换、作者/关注按钮、静音按钮区域不触发视频手势。切换页面、进入后台或离开当前时间线会暂停并释放播放器。

构建60按当前窗口重新排列预载优先级：远处任务让位给最近缺失作品；视频在当前页起播或重新缓冲时，后续视频完整文件下载暂停，恢复缓冲后继续。当前图片继续与预载共用缓存下载，不重开第二个写入任务。并发、网络条件、单文件上限、空间保留及失败后的重试边界继续由原有缓存和队列管理。三次本地门控对照只证实调度等待减少，没有观察到 AVPlayerItem 就绪时间改善，不能将其解释为真实站点首帧提速。

本轮的架构调整集中在实际新增边界：`FilterPresetStore` 负责账号／入口隔离与原子保存，共用方案界面负责所有入口的展示和操作；`TimelineLane` 的画面、弹层与生命周期分开表达；`MediaCache` 提供内存中的前台播放需求，`MediaPreloader` 据此安排下载。没有为方案复制分页、媒体缓存或账号写入逻辑。后续若继续改造，优先将会话传输与媒体文件管理按所有权拆开；目前仍有视图依赖 `SiteSession` 和共享实例，不声称已完成全面解耦。

构建26在同作品短暂进入后台或被登录窗口覆盖时保留这次位置和手动暂停状态；离开普通作品焦点后仍遵循原来的新访问行为。进度条跳转完成后才提交进度，迟到回调按播放器、作品和上下文核对。

## 最近浏览与接着看（构建24起；构建28原地恢复）

入口位于时间线左上角时钟和「我 → 最近浏览与接着看」。图片加载完成或视频显示画面后，在当前页连续停留2秒才计入；详情覆盖、模糊未揭示、后台或离开页面不计。记录按作品ID保留最近30天，最多5,000条，按日期分组，支持图片/全部/视频、作者名/作品编号查询及继续展开。视频约每5秒保存进度，并在暂停或播放器释放前补存；时长未知不伪造为0秒。

推荐和关注各保留一个最多30项的阅读段、当时的筛选、焦点与视频进度。构建28点击“接着看”才在当前时间线原地替换；先重新核验作品、作者关系、当前账号内容范围及本机屏蔽，成功后一次提交列表、筛选与焦点。读取失败保留原列表与焦点，迟到请求不能覆盖新状态。不增加导航层级，也不混拼两段列表。提示点击恢复即收起，×只隐藏该记录的提示，不删除历史；推荐／关注的隐藏状态合并保存。

只有保存窗口覆盖真实源尾部时才同时保存有界的分页位置。旧记录或中间窗口缺少该边界时明确提示从当前结果起点续扫，以作品ID和稳定媒体身份跳过恢复片段，不伪称精确历史续页。失效位置保留已恢复作品，提供重新获取当前结果。关注恢复时重新核对当前关注集合并补回缺失的作者ID。恢复视频离开再返回保留这次最新位置，接近片尾从头播放。

构建26允许当前账号已有的视频记录在重新进入后的前2秒更新播放位置；新作品仍需2秒有效曝光。已有续播位置会等到有效的有限时长后再恢复，避免暂时未知的时长消耗保存位置。历史格式和原有账号目录保持兼容。

历史仅在本机按当前/已知账号隔离，退出账号不会把记录并到匿名账号。文件存作品ID、作者、类型、时间、进度及筛选；构建28新增可选且与真实尾部配对的opaque分页位置，旧schema1记录仍兼容。不保存媒体URL、Cookie或授权材料。打开作品和缩略图前以当前账号按ID重新核对，当前分级、标签和作者屏蔽继续生效；离线时保留历史文字；启用标签屏蔽而标签尚未核实的条目暂不展示，不承诺历史媒体整段离线可播。媒体仍复用原缓存，不为历史另外下载或复制收藏。实际解码发现站点类型误标时，历史按真实呈现的图片／视频类型保存，视频断点继续可用；目录筛选仍保留站点原始语义。

## 本机作者屏蔽与实际媒体格式（构建28）

作品详情和作者页可屏蔽作者，「我 → 屏蔽作者」查看和解除。正整数作者ID优先；缺少ID时仅使用已核验且唯一的用户名回退，不把匿名作品整体屏蔽。时间线、搜索、作品网格、收藏、历史和离线呈现使用同一名单；解除屏蔽可从已加载原始候选回填。主动访问被屏蔽作者时显示明确状态与解除按钮。名单持久化在本机，不调用站点账号屏蔽接口，不取消关注或删除收藏、历史、媒体文件。

图片先按字节经ImageIO解码，响应MIME和扩展名不作为最终类型判断。合法GIF／动画WebP在聚焦页实际播放，遵循自动播放开关；单击可暂停／继续，边缘切换和双击作者沿用现有手势。网格只用静态预览。动画最多处理400项帧元数据、120秒，采样32帧／384px，单并发解码，离页释放；较大动画显示明确限制，不假装已完整支持。

可播放的MP4若被站点标为图片，会切到播放器并按视频保留缓存；有效图片即使MIME写为video也可以解码。视频封面优先真实图片，必要时对同一已知CDN资产请求保留blur等参数的静态变体；不改签名query或未知主机。只有当前聚焦视频才允许本地首帧提取：远程最多8MiB、解码最多8秒、512px、单并发；网格不为取首帧批量下载视频。401／403及HTML／JSON错误保留失败，不换身份或绕过；坏缓存仅修复对应条目，不清用户全缓存。

可以关闭记录、长按删除单条或清空当前账号历史和恢复点。不会删除离线收藏、浏览缓存或站点作品，也不写云端收藏/关注。损坏、未知版本或账号不符的历史文件保留并报错，不自动覆盖。模拟器专用 --qa-history-screen 使用独立Caches/CivitHistoryQA和PG种子；不会写入手机或真实历史目录。

## Google 登录与账号

登录使用 **SFSafariViewController 系统浏览器**中的 Civitai OAuth，采用已注册 Public client、Authorization Code + PKCE S256，无 client_secret。应用内临时启动 `127.0.0.1` 回调监听器，只接受一次匹配 state 的回调，完成或取消后关闭。这不是外部服务。

授权凭据仅保存在本机 Keychain，使用 `WhenUnlockedThisDeviceOnly`；不写入工程、UserDefaults、日志或交付文件。刷新合并进行，用会话代数阻止退出后迟到的结果恢复登录。匿名请求必要时使用非持久化 WebKit 的真实站点源，不伪造请求头。

原生账号内容偏好覆盖账号内容分级和成熟内容模糊偏好。保存前核对账号，保存后读回服务器值。昵称、邮箱、账号安全等完整官网设置尚未移植。

「我的关注」提供关注顺序／名称A–Z两种模式，分别支持最近／最早、A–Z／Z–A，保存在本机。先完整读取并核对当前账号关注集合，再统一排序；每批最多20页、每页50位，超过1000位可继续读取。关注顺序保留服务端createdAt DESC，不用作者ID推断时间。同集合先取关再重新关注通过本机确认的关系revision失效旧排序缓存；相同集合的普通刷新不增revision。进入作者返回保留原列表位置。

关注/取消关注使用站点 toggle 接口：先读当前关系，最多写一次，再读回验证。结果不明时先读回，不自动重复 toggle。关注时间线按新关注集合移除不再关注的作者作品。

## 收藏作品

作品全屏页的书签按钮打开原生收藏夹选择器，可以同时保存到多个自己的图片／视频收藏夹，取消勾选则从对应收藏夹移除。新收藏默认勾选上次保存的收藏夹；未记忆时选择私密「收藏作品」，已有收藏按服务器真实状态显示。默认值按账号隔离，打开选择器不会直接写入。「我 → 我的收藏」展示当前账号拥有的媒体收藏夹；进入后按 Images / 全部 / Videos 筛选，点击作品使用现有整屏查看器、视频手势与磁盘缓存。

Civitai 将图片和视频统一视为 `CollectionType.Image`。原生列表只包含自己拥有的 Image 或混合类型收藏夹，不向其他作者的收藏夹或比赛投稿。新建收藏夹明确使用 Private 读取和 Private 写入；已有收藏夹展示实际可见范围。收藏仅保存引用，不上传或删除原作品，也不是给作品点赞。

收藏需额外的 `CollectionsRead`（131072）与 `CollectionsWrite`（262144），与原有权限合计 917539。旧授权继续支持浏览和关注；收藏入口按需提示补充授权，不强制退出。刷新旧 token 时以它原有的 scope 校验，避免升级版本导致旧登录失效。

保存前读取账号和当前收藏关系，只发送用户实际改动的收藏夹增删，不覆盖其他关系或标签。保存后再次从服务器读回；结果不明时不重发写操作，提示先刷新。活跃作品收藏状态短暂复用 60 秒，打开收藏选择器总是强制读取，旧请求不能覆盖较新的读回。收藏夹列表、游标、类型筛选共用现有防重复和代数隔离逻辑。这里不承诺离线收藏写入队列。

收藏构建、安装和真实账号验收分别记录；只有本地检查通过不能视为账号收藏同步已通过。

## 离线收藏与精细空间管理

「我 → 离线收藏与空间管理」独立管理本地副本；默认开启自动保存，包含账号现有的全部可访问图片／视频收藏，而非只处理新增收藏。自动扫描自己的 Image 或混合收藏夹，按作品 ID 跨夹去重。默认仅 Wi-Fi 下载，一次下载一项；启动、回到前台、账号收藏变化时同步，前台每 5 分钟补查。iOS 进入后台时暂停，回到前台后扫描并复用已完成文件；没有声称无限后台下载或部分文件的 HTTP 断点续传。

独立上限默认 10 GB，可选 1 / 5 / 10 / 20 / 50 GB，不预先占用空间。空间满或剩余空间不足约 1 GB 时暂停，不自动逐出已经下载的收藏。浏览缓存仍是原来的 5 GB 默认与 LRU；清理浏览缓存不会删除离线收藏。两个额度独立，实际占用可以相加。

本地文件保存到按账号隔离的 Application Support 目录，排除系统备份并启用设备数据保护。索引只保存作品 ID、类型、作者、收藏夹引用、时间、大小和状态；不保存媒体 URL、签名 URL、Cookie 或授权材料。本机确认过的公开账号 ID 绑定在既有 Keychain 登录记录中，便于离线冷启动识别自己的目录；临时断网或服务错误不清除该绑定。

空间管理支持：

- Images / 全部 / Videos 与已下载、未下载、已取消收藏、待核对、失败状态筛选。
- 按占用大小、保存时间、最近打开排序；显示每项大小、保存和打开时间。
- 多选删除手机副本，云端收藏不变。手动移除会记入排除项，避免自动下载立即重新占用空间；「重新下载全部」可恢复。
- 取消云端收藏时保留本地副本。完整扫描缺失后还会读作品的账号收藏关系；共享／比赛收藏夹中的引用也用于保留判定。
- 「核对并清理已取消收藏」逐项重新联网检查；有勾选时只处理所选项，否则处理全部本地记录。仅已确认无账号收藏关系的本地文件可清理，查询失败保持「待核对」。从一个夹移除而另一个夹仍有引用时不会清理。
- 清理全部离线收藏会同时关闭自动保存，浏览缓存和 Civitai 收藏仍保留。可识别的索引外文件会恢复到待核对列表。

构建24时，手机无线更新后已独立读回 **0.3.0 (24)**。包含构建22的联合过滤、本地标签库与统一去重，以及构建23的标签库空间显示修复。gaping+realistic的真实账号8条AND匹配和本地1313项索引是构建22验收结果；该轮未重新修改账号关系或执行该组合请求。构建24新增最近浏览与接着看，实际验收边界见 build/ui24-acceptance.json。随后真机已正常启动并观察到时钟入口；模拟器PG视频实际seek已读回完成，目标1.779687337秒、实际1.778333333秒。该轮手机最近浏览与关注恢复的交互检查仍受镜像连接中断/超时影响。102份原有视频/封面、4,790,920,839字节更新前后路径、大小及修改时间一致；未导出媒体或做内容哈希。

## 缓存

默认 **5 GB**，可选 **1 / 5 / 10 / 20 GB**，按十进制字节计算；不会预先占用空间。图片内存预算 64 MiB，解码最大边 2048 像素。

磁盘文件名仅使用 URL 哈希，不保存媒体 URL 清单。按最近使用时间逐出，保护当前播放器和即将预取的文件。空间不足时停止预取并提前清理，目标保留约 1 GB；受保护文件可能令瞬时用量超过目标。主动播放也可能直接流式读取，不保证整条影片都永久下载。

媒体预载默认准备后续6条作品，可选3／6／10条，先准备原媒体，再处理封面。61候选源码另外提供2／4／6／8路并发、默认4路；图片和视频共用这些后台下载槽位。缓存下载总队列有10个槽位，最多新准入8个后台任务，当前作品优先；当前播放缓冲时让出后续视频预载，恢复后自动继续。已交付的60版仍使用原来的2个后台任务及4并发下载队列。

视频预载默认限非昂贵、非受限的Wi-Fi／有线网络。图片单文件上限16MiB，视频预载硬上限512MiB；实际准入额度还扣除受保护文件、并行下载、兼容修复及前台余量，保留约1GB磁盘空间。普通视频下载入口原有64MiB合同保持不变。超过限制保留失败原因，不把整条视频读入内存；清理后迟到结果不会重新写回缓存。

时间线完整列表和远端游标只保留在当前运行会话。构建24可按作品ID恢复一段最多30项的浏览位置，并重新核对当前账号权限；没有把它称为完整离线时间线。媒体磁盘缓存可以跨启动复用。

## 筛选与失败边界（构建 13 起）

设置新增本机「屏蔽标签」，默认列表为空。按站点返回的真实标签名精确匹配，忽略大小写、首尾空白和兼容字形；不猜同义词或识别画面。启用后，缺少标签的作品暂不展示并说明原因，保留后续游标；涵盖推荐、关注、作品榜、作者、收藏和离线查看。历史离线记录可联网补查标签，不重下媒体；已有文件不会因为屏蔽而删除。真机运行后，51 项已有收藏的标签元数据已补齐。

作者榜新增「不限时间／近 24 小时／7 天／30 天／90 天」。依据当前账号可见的已发布图片或视频帖子 `publishedAt`；保留原排名。每批最多核实 40 位作者，每批并发 3 个查询，每位最多 4 页、每页 5 帖；结果缓存 10 分钟。未查、失败或扫描受限的作者单列待核实，页面显示覆盖人数，不能把局部核实说成全榜完成。真实账号此接口尚待原生验收。

时间线只有一个加载入口，按作品 ID 及 Civitai 媒体 UUID 去重；其他主机按完整 URL。推荐/关注分开记忆，刷新后重新建立已见集合，不对画面或封面做相似度判断。所有在线列表默认按作品ID及明确的媒体身份展示去重；同Civitai媒体UUID的清晰度变体归为同媒体，陌生主机只按完整URL，不做画面相似识别。设置“合并相同媒体”可关闭；原始不同作品ID和各自收藏关系保留，收藏写入仍只针对当前ID。离线管理保持逐作品文件记录。继续加载页接上新内容，不回到第一项；筛选移除当前项时向后寻找仍可见项。

仅 AVPlayerItem 明确失败才启动恢复：刷新一次地址，绕过缓存再试。恢复后仍是 404/410、缺少解码器，或本地文件确实不存在时才可自动到下一条；连续六次自动前进后停止。缓冲、加载、鉴权、限流、网络、服务器及未知错误保留加载/重试状态，不按超时自动跳过；不保存永久黑名单，不删除媒体或收藏关系。

状态和排序为离线空间页的独立行；多选只选择、完成清空选择。当前真机目录读回 51 段视频及封面、4.79 GB；更新前后文件路径/大小/修改时间一致。空间页构建 15 的模拟器空库布局与菜单已观察；构建16的紧凑多选详情与预填搜索已在模拟器实际组件验证；构建20的标签查询和关注排序已在手机镜像验证。

视频时长区间已有原生控件。客户端按已核实的可靠时长筛选，未知时长不能当0秒，也不计入符合条件的预载数量。遇到不合条件的页会继续按游标查找，直到补足窗口、源结束或出现真实请求错误；这不代表站点提供了全站时长查询，也不通过批量下载视频来探测时长。53补齐了恢复单条队列后只翻一页的遗漏路径。

## 搜索、详情、标签目录和简介（构建 22）

统一「组合搜索」页分别设置标题文本、可选作者和最多 8 个标签；所有有效条件取交集。条件可单独移除或清空，空条件不会请求全站作品。作者昵称最多 20 位站点候选。标题按作品帖标题前缀匹配，再读取每帖的完整媒体分页；文本不等于 prompt 或描述全文。搜索支持全部/图片/视频、即时范围/排序筛选和本机屏蔽。

标签名称搜索、常用列表和可展开目录使用同一个入口和结果列表：SQLite结果先显示，输入停顿300ms后自动补查站点，按真实标签ID合并；在线返回自动落库，无需手动切换本地／在线。按站点与当前/已知账号隔离，不经过媒体缓存LRU。数据库上限128MiB，按ID upsert名称/分级，原始杂项保留、默认展示隐藏纯符号/纯数字/年代。目录分页分别保留本地与在线续页；相同查询在短期内恢复完整快照，防止刚落库的在线结果改变重复查询顺序。在线失败仍保留本地结果并允许重试，本地保存失败也不丢弃已取得的在线结果。

初始同步轮换A–Z和0–9，每批最多8页、每页200条元数据，单并发并间隔750ms；前台每30秒尝试下一批，默认仅WiFi。页写入与断点同事务，暂停/切后台可续；完成的前缀24小时后轮换复查。未发现远端更新时间/变更游标，所以这是“重读前缀、增量合并落库”，不是真正只拉远端变更；未重见条目不自动删。初始字母数字和已请求前缀不是全站总量证明。库损坏、容量不足、未知schema保留已有文件并显示错误。

官方多标签输入在已检查路径是OR。无标题的多标签AND由客户端先各读一个最多100条的候选页，按实际观察到的匹配密度选流（已耗尽流优先），之后沿这个流原游标筛选全部标签；不再按ID大小推断候选稀有度。每批仍有限页数、显示已检查页数并保留续页；空批不表示全站无交集。标题是作品帖标题前缀，不是描述/prompt全文。构建22真实 `gaping + realistic` 已读回8条AND匹配，并有后续。

作品详情改为紧凑换行标签块，点选多个标签后底部「组合搜索（N）」带入统一搜索页，继续添加文本/作者；长按可屏蔽或撤销，不再为每个标签显示大行按钮。缺少 ID 的离线标签先按真实名称查询确认；解析时冻结选择、清空和刷新，导航前核对账号、选择快照与取消状态，避免进入旧条件。屏蔽即时保存，只延迟当前详情所属列表的重算，新搜索立即使用当前屏蔽；关闭详情保留相对位置，不删除收藏/媒体。

作者原始 profile.bio 转换为原生纯文字，长文可展开；安全 http/https 链接手动打开，不执行 HTML、脚本或远程图片。未取得、失败、空简介和不可见分别显示。

Debug 显式参数 `--readback-client` 串行运行正常会话的只读检查，报告位于 QAReadback/client-build<构建号>.json，仅含计数、状态和非秘密分级数值，不含凭据、URL、响应正文或媒体。构建20的报告已独立读回。`--probe-tag <名称>` 查询标签元数据；`--readback-local-search` 对用户标签组合做纯作品元数据计数，并将标签元数据落入本地索引后检查本地查询（不请求该词媒体文件、不导出URL或响应正文）。诊断启动落在搜索页，并暂不执行离线收藏下载。模拟器专用 `--qa-search-screen`、`--qa-offline-screen` 只打开实际组件，不注入账号或用户文件。

构建25起缩略图使用一条可取消的有界加载队列，最多4个并发、64个等候；不再因并发已满直接放弃封面。图片实际解码成功后才写入缓存；旧的不可解码缓存只修复对应缓存文件，保护离线收藏文件。失败显示重试入口，不再由另一套加载器隐藏原始失败。`--readback-unified-tags` 仅查询标签元数据和最多3张公开PG视频静帧，输出计数与布尔状态，不证明全站标签完整。

## 本机诊断记录（构建26）

入口为「我 → 本机错误与诊断记录」。仅记录时间、版本、枚举分类／错误码及受限HTTP状态／数量，不记录账号、作品编号、请求地址、关键词、任意错误文本或认证资料。最多7天、1,000条、4个各256KiB文件；重复和高频事件会合并或限速，诊断读写失败不影响业务操作。可以查看、准备导出、通过系统分享以及清除；没有自动上传。

用户报告看视频回到桌面的事件，当前未找到同一时段匹配的应用崩溃、watchdog或明确Jetsam终止记录。较早的磁盘写入资源报告标注 `Action taken: none`，不能据此判定这次退出原因。原始失败和独立摘要均保留在 `build/ui25-*`，原因仍为UNKNOWN。
